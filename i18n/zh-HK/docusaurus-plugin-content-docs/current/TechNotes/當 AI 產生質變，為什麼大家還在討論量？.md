# 當 AI 產生質變，為什麼大家還在討論量？

星忘塵 Nebula Walker · 創象引擎 MYTHOGEN ENGINE

---

FABLE 5 出了。

社群的反應是什麼？

> 「趕緊重構程式碼。」  
> 「長任務完成率 29%，比上一代高一倍。」  
> 「下週二開始收費，趁現在把事情做完。」

這些反應完全合理。做產品的人有 deadline，接案的人有客戶，創業的人分秒必爭。拿到一個更強的工具，第一件事當然是用它解決眼前最痛的問題。這不是短視，這是生存。

但我想多說一件事。

不是說那些事不重要。而是說，也許還有另一層東西值得注意。
![](./images/Gemini_Generated_Image_g9neyhg9neyhg9ne.png)

## 兩重變化：量變與質變

每一次 AI 的智力跨過某個臨界點，都會產生兩種變化：

1. **量變**：同樣的事做得更快、更好、更便宜。
   - 長任務完成率從 13% 跳到 29%，這是量變。
   - 程式碼重構從三天變一天，這是量變。
   - 量變有巨大的商業價值，它直接影響你的成本和交付速度。
2. **質變**：突然可以做以前根本做不到的事。
   - 不是同一條賽道跑得更快，而是出現了一條以前不存在的賽道。

社群目前的討論，幾乎全部集中在第一種。

這很正常。量變容易衡量、容易比較、容易變現。質變不是——它模糊、抽象、短期內可能一分錢都賺不到。

但歷史上真正改變格局的，往往是質變。

---

## 從噪音中辨識信號：FABLE 的真正價值

上一篇文章裡，我用了一個夢和一個圖書館來講 FABLE 讓我真正在意的事。

不是它寫程式比較強。不是它長任務完成率比較高。

而是它似乎第一次有能力做到一件以前沒有任何 AI 做到的事——**從海量的噪音裡辨識出被錯誤埋沒的信號**。

- **不是**搜尋，**是**判斷。
- **不是** retrieval，**是** recognition。

如果這個能力是真的，它的應用範圍遠遠超過寫程式碼：

- **DNA 序列**裡被忽略的 pattern。
- **學術論文**裡被排序系統埋葬了二十年的滄海遺珠。
- **社群演算法**的根本性重構——不是推薦你「可能喜歡」的東西，而是推薦你「應該知道但不知道自己需要」的東西。

這些事的共同點是：它們不是「做得更快」的問題，而是「以前做不到」的問題。

## 生存是第一步，但質變會「死人」

我不是說大家應該放下手上的工作來思考哲學。

手上有 codebase 要重構的，趁窗口期趕緊重構，這是對的。有產品要上線的，用最強的工具壓縮時間，這也是對的。生存永遠是第一位的。

我自己也是一個每天在想怎麼活下去的人。

但有一件事必須提醒：**質變不是哲學課的題目。質變是會死人的。**

每一次破壞性創新，都會捲死一批看起來理所當然的公司和工具。這件事我們已經親眼見過：

* **套皮應用的黃昏 (2022-2023)**  
  大量創業者用 OpenAI 的 API 做套皮應用——套一層介面，加一些 prompt，就是一個產品。有些人融到了資，有些人賣了不少訂閱。然後 ChatGPT 開了自己的 GPT Store，Google 跟進，每一家大模型都開始做自己的應用商店。一夕之間，整個套皮生態被掃掉大半。先行者開發，平台仿效，然後先行者死掉。這個劇本在兩年內重複了好幾次。

* **工作流自動化 (Workflow Automation) 的隱憂**  
  Make、n8n、Zapier 這些平台，教人用的課程現在賣得很好，講師收入也不錯。但如果大模型真的做到了 agent-level 的任務編排，整個「你來拉線接節點」的 layer 可能直接被跳過。教別人用這些工具的人賺到了學費，但真正 all-in 把公司建在這個 layer 上的人，可能會血本無歸。

而且不要以為「multi-agent」、「協作框架」這些現在最熱的概念就安全。它們跟 API wrapper、跟 workflow automation 的本質是一樣的——都是建立在某個中間層上的框架。

> 💡 **中間層的命運就是被跳過。今天的新範式，明天的套皮。被淘汰的從來不是技術，被淘汰的是框架。**

---

## 框架的半衰期與不變的底層能力

這不是說框架不重要。框架當然要學——企業要求你會 Java 你就學 Java，市場需要 Agent 開發你就學 Agent 開發。這是生存，沒有什麼好討論的。

但有一件事值得記住：**框架的壽命越來越短了。**

* **過去的標配**：Flash、jQuery、AngularJS、Hadoop、Docker Swarm、TensorFlow 1.x —— 每一個都曾經是市場標配，每一個都曾經養活過大量的人。學它們在當時完全正確。但如果有人以為可以靠它們吃一輩子，那就錯了。
* **現在的工具**：n8n、MCP、Agent Framework 也是一樣。今天一定要學，但要預著三到五年就會換一輪。

問題不是學不學，而是你有沒有意識到自己站在哪一層——以及這一層什麼時候會被跳過。

速成課程賣的永遠是最上面那一層，因為那一層最容易教、最容易賣、市場需求最即時。「三天學會 n8n 自動化」、「一週精通 AI Agent 開發」——課程賣得出去，因為框架確實可以速成。

但框架底下那些東西：
- **系統思考**
- **抽象能力**
- **理解 trade-off 的直覺**

這些不能速成，也不會被淘汰。它們不是讓你不用學框架，而是讓你在框架換代的時候，不用從零開始。

這就是質變的另一面。它不只是「可以做新的事」，它還意味著「舊的事會消失」。你不去想質變，不代表質變不會來找你。

## 結語：開啟以前無法想像的思考

所以「想一想質變」不是閒情逸致。對某些人來說，這是生死問題。

但如果你做完手上的事之後，還有一點餘裕，也許值得想一下：
1. 這個東西跑得更快，我已經知道了。但它還能做什麼我從來沒有想過的事？
2. 以及，它會不會讓我正在做的事變得不再需要？

> **AlphaGo 不是「下棋更快的程式」。它下出了人類棋手從來沒有想到的棋路。**

也許 FABLE 最有意思的地方，不是它幫你做完了什麼。  
而是它讓你第一次可以開始想，有哪些事情是以前連想都不會去想的。
